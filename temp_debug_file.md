Per-Item DB Queries (`find_attack_status`)\n- **Issue**: For each site/asset, two separate DB queries are made (min_minutes and max_minutes timeframes)\n- **Impact**: O(N) queries where N = sites + assets\n- **Potential**: Batch queries or cache results\n\n### 2. Per-Item DB Writes\n- **Issue**: Each site/asset/account is saved individually\n- **Impact**: O(N) write operations\n- **Potential**: Bulk write operations\n\n### 3. Redundant Account Queries in `find_account_status`\n- **Issue**: Re-queries sites and assets per account instead of using cached data\n- **Impact**: Additional O(accounts × items) queries\n- **Potential**: Use already-fetched data from handle_sites/handle_assets\n\n### 4. Intersection Check Per Item\n- **Issue**: `intersection([\'mssp-portal\', \'defense-pipe\', \'vcpe\'], services)` called per item\n- **Impact**: Minor, but repeated list operations\n- **Potential**: Pre-filter accounts with relevant services\n\n---\n\n## Feature Flags Design\n\n```python\n# ==============================================================================\n# FEATURE FLAGS - Toggle
