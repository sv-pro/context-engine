## The Trust Problem

ReAct agents are powerful, but how do you trust their answers? An agent might:
- Stop searching too early
- Misinterpret tool outputs
- Synthesize incorrect conclusions
- Hallucinate despite having context

The `brain-react` pseudo model addresses this with **verification, confidence, and learning**.

## Answer Verification

After the agent produces a draft answer, the `KnowledgeBaseVerifier` validates it:

```python
class KnowledgeBaseVerifier(dspy.Module):
    def forward(self, question: str, draft_answer: str):
        # 1. Extract entities from question + answer
        entities = extract_entities(question + " " + draft_answer)
        
        # 2. Query facts for each entity
        facts = []
        for entity in entities[:5]:
            facts.extend(get_facts(subject=entity))
        
        # 3. Search for corroboration
        search_results = search_knowledge_base(question)
        
        # 4. Cross-check with rules
        rules = get_rules(limit=3)
        
        # 5. Verify against knowledge
        return self.verify(
            question=question,
            draft_answer=draft_answer,
            knowledge_context=format_context(facts, search_results, rules)
        )
```

The verifier produces:
- **Verified answer** — potentially corrected
- **Status** — `Correct`, `Partial`, `Incorrect`, or `Unverified`

### Defensive Logic

If the verifier says "Incorrect" but the draft contains specific values (numbers, hostnames), the draft is kept. Why? The verifier may lack enough context to validate correct answers.

```python
if verification_status == "Incorrect":
    has_specific_values = bool(re.search(r'\d{3,}|\bredis-\w+\b', draft_answer))
    if has_specific_values:
        logger.warning("Verifier said 'Incorrect' but draft has values - keeping draft")
        final_answer = draft_answer
        verification_status = "Unverified"
```

## Confidence Self-Assessment

A dedicated DSPy signature estimates answer quality:

```python
class EstimateConfidence(dspy.Signature):
    question: str = dspy.InputField()
    gathered_info: str = dspy.InputField()
    current_answer: str = dspy.InputField()
    
    confidence_score: float = dspy.OutputField()  # 0.0 to 1.0
    missing_aspects: str = dspy.OutputField()
    recommendation: str = dspy.OutputField()  # "finish" or next steps
```

This enables:
- **Early termination** when confidence is high
- **Targeted follow-up** when aspects are missing
- **User warnings** when confidence is below 0.8

```python
if confidence < 0.8:
    logger.warning(f"⚠️ Low confidence ({confidence:.2f}) - answer may be incomplete!")
```

## The Investigation Artifact

Every successful ReAct session generates a markdown artifact:

```markdown
---
type: investigation
status: closed
date: 2025-12-30T20:00:00Z
query: "What happens if the DB connection fails?"
tags: [react, investigation, auto-generated]
---

# Investigation: What happens if the DB connection fails?

## Executive Summary
The system pages the DBA on connection failure...

## Reasoning Trace

### Step 1
**Thought:** I need to check for failure handling rules...
**Action:** `get_rules(domain="database", severity="critical")`
**Observation:** > RULE_DB_001: IF connection fails THEN page DBA...

### Step 2
**Thought:** Let me verify with search...
**Action:** `search_knowledge_base("database connection failure")`
**Observation:** > Found: Database_Operations.md...

## Methodology
This investigation was automatically generated by the Context Engine ReAct agent.
```

### The Self-Improvement Loop

1. Investigation saved to `volumes/raw/investigations/`
2. File watcher detects the new file
3. File ingested into knowledge base
4. **Neurosymbolic distillation skipped** — investigations don't generate facts/rules
5. Investigation becomes searchable context for future questions

Why skip distillation? Investigations contain reasoning traces, not verified facts. Distilling them would propagate unverified conclusions as authoritative — a recipe for hallucination loops.


## When to Use brain-react

- **Multi-hop questions** — "A relates to B which affects C"
- **Procedure lookups** — need full sections, not snippets
- **Relationship queries** — "What calls what?"
- **Troubleshooting** — complex investigation required
- **High-stakes answers** — verification matters
